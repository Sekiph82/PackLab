# PackLab local disk hygiene

PackLab development commands must leave owner files, active worktrees, and the stable OWNER DEV runtime intact. Reproducible test and build scratch belongs in the PackLab-owned temporary roots below and is removed as soon as its command finishes.

## Test runs

Run the full local suite with `tools/dev/run_packlab_tests.ps1`. It checks C: free space first and refuses a disk-heavy run below 40 GiB. It also refuses work when the allowlisted PackLab temp/build/staging footprint is already over 8 GiB. Each invocation gets one unique marked directory below `%TEMP%\PackLab\pytest`; pytest receives that run's explicit `--basetemp`. During the run, the wrapper takes bounded snapshots of all allowlisted PackLab disposable roots, including shared `%TEMP%\PackLab`, repository build/dist/staging and local pytest output, plus only OWNER DEV staging/temp. A scan is capped at 2 seconds or 100,000 filesystem entries; inaccessible, locked, reparse-root, or over-bound measurement fails closed and stops the launched process tree. The wrapper monitors C: free space and stops the process tree if free space falls below 40 GiB, basetemp exceeds 4 GiB, one fixture exceeds 2 GiB, or all disposable PackLab data exceeds 8 GiB. It reports the corresponding `PACKLAB_*_BUDGET_EXCEEDED` or `PACKLAB_DISPOSABLE_MEASUREMENT_FAILED` code. It first requests a graceful process-tree stop and uses forced termination only after a 10-second timeout. It preserves pytest's exit code when limits are not hit, writes only the last 200 output lines to ignored `reports/_local/pytest` on failure, and removes the marked run directory in `finally`.

`tests/ci/test_packlab_test_runner_behavior.py` exercises the wrapper with tiny byte thresholds and small synthetic files. It covers normal and nonzero exits, quiet output, asymmetric stream EOF, each disk quota, non-pytest staging growth, process-tree shutdown, unrelated-process survival, measurement failure, and marked run cleanup. Contract-test mode accepts only lower positive limits, uses a fixed test child, and confines scratch data to `%TEMP%\PackLab\runner-contract`.

Use `tools/dev/packlab_disk_hygiene.ps1 -Mode inventory` to inspect the PackLab temp roots, OWNER DEV roots, pytest leftovers, and uv cache. Inventory lists cache roots without recursively walking them by default; do not add `-MeasureInventoryBytes` while active shared-cache consumers exist. Use `-Mode preflight` before disk-heavy work and `-Mode post-task -Apply -CleanupOwnerDev` after a validation batch. Add `-JsonSummaryPath <path>` for a machine-readable summary. The helper prints each deletion candidate, defaults to dry run, requires an explicit `-Apply`, checks its allowlisted root and ownership/manifest evidence, skips active test processes and active OWNER DEV paths, and fails closed on access/measurement errors. The optional Desktop OWNER DEV cleanup keeps the verified current and newest distinct smoke-passing previous release, and removes only older manifest-identified runtime snapshots after confirming the Desktop launcher and shortcut identities. Legacy `%LOCALAPPDATA%\PackLab\OwnerDev` `logs`/`releases`/other ambiguous content is retained and measured read-only; the whole tree is never removed. Candidate-specific marked staging/temp cleanup also skips when an OWNER DEV process is active. Historical `%TEMP%\pytest-of-sekip\pytest-<number>` runs may be removed only by passing the individually verified numeric run IDs; the helper never scans and removes all system pytest runs on its own.

## Build and cache data

Put PackLab-only disposable builds, source extraction, and staging below explicitly named PackLab temp roots; remove them after retaining required compact evidence. Do not remove canonical source, project checkouts, active/dirty/ambiguous worktrees, owner data, the Desktop `PackLab.exe`, active or previous-good OWNER DEV runtimes, or unrelated caches. Retire a Codex worktree only with Git worktree commands after verifying it is clean, published/reachable, inactive, and not current M16 work.

Keep total disposable PackLab temp/build/staging below 8 GiB during work, any single generated test tree below 2 GiB, and completed disposable data below 1 GiB at handoff. Prefer minimal fixtures over copying repositories, `.venv`, runtimes, or caches. After a major local validation batch, inspect C: and the uv cache, then use `uv cache prune` only when no active process is running from the shared uv cache. When Godot, Blender, or MCP processes are active, report `DEFERRED_SHARED_UV_CACHE_ACTIVE`, record a bounded process sample, and do not stop them or block hosted PackLab CI because of the deferral. Do not use routine `uv cache clean`. Inspect pip cache and only reduce it with pip's supported cache command if it exceeds 2 GiB. Never delete Python installations or active environments.

Every implementation log records disk-free bytes before/after, reclaimed bytes by category, retained worktrees and the reason, and any locked paths. Personal files and Hugging Face, Puppeteer, browser, GPU, and Codex runtime/cache data are outside the automatic cleanup allowlist.
