## Implementation

- Added `core/src/packlab_core/vggt_worker.py`, an offline-only CLI worker. It validates the exact local upstream code pin and clean source checkout, exact checkpoint size/SHA-256, and ordered image file identities before importing torch or VGGT. It uses the pinned VGGT preprocessing/camera APIs and the V07 streaming safetensors loader, then writes a bounded finite XYZ PLY sample and camera result JSON without local paths in results/errors.
- Added `VGGTSubprocessWorkspaceEngine` in `core/src/packlab_core/neural_reconstruction_runtime.py`. Its capability check imports no model packages. It enforces a physical-memory budget and exact checkpoint pin before worker launch, uses offline Hub flags, strips Hub token variables from the child environment, bounds process time/result/output size, and supports cancellation.
- The worker result parser fails closed on schema/key/revision/order/count/finite-matrix/transform mismatches. The child process removes known Hugging Face token variables, forces Hub/Transformers offline mode, disables CUDA visibility, and the worker reasserts those settings before importing torch and rechecks the configured physical-memory floor immediately before importing torch or constructing VGGT. Model and preprocessed image tensors are explicitly placed on CPU. The parent validates the entire bounded ASCII PLY structure, declared/actual vertex count, and every finite XYZ row before accepting the output. Parent request serialization is capped at 1 MiB, image count at 100, and worker lifetime at 3,600 seconds. Both worker request and parent result reads use size-limited reads. Error results use exclusive file creation to avoid overwriting a pre-existing path. The point-cloud writer scans finite XYZ rows in bounded chunks, samples only finite rows, and fails when no finite points remain; the parent rejects empty point-cloud responses. Output is capped at 50,000 finite samples.
- Added `cleanup_after_publish` to `VGGTOutputArtifact`. Publisher and workspace-runtime cleanup delete only explicitly marked regular files after validating containment below the runtime output root; owner/unmarked files remain. This cleanup also runs on publication failures and adapter exits after inference.
- Added focused synthetic worker protocol, camera/result, point-cloud and safe-cleanup tests. This continuation also extracted the subprocess wait/cancel/timeout handling into a directly testable helper and added five synthetic checks: successful exit, cancellation, cancellation escalation to kill, timeout kill, and non-zero worker exit.
