## Demonstration

`tests/core/test_pl0391_label_mockup_demo.py` holds two tests:

- **Lineage test (runs in hosted CI; OCP only).** It builds the synthetic hybrid scene: an OCP box plus a cylinder boss, with FRONT, BACK and WRAP label zones and synthetic 2×2 PNG artwork. From each scene binding's own metric surface binding and placement it creates a print-intent dieline and exports the SVG. It then asserts:
  - the SVG is bound to the exact Design Model, BREP, zone and placement revisions;
  - the scene overlay shares the same model, BREP, metric binding, artwork, mapping and assignment revisions;
  - `mm_unverified`, `DEFERRED_OWNER_VALIDATION`, `print_fit_verified=false`, `print_ready=false` and `manufacturing_authorized=false` stay visible.
- **Rendered mockup (real Blender 5.2.2 LTS; `PACKLAB_REAL_BLENDER_SMOKE=1`).** It renders a 512×512 three-quarter view through the PackLab scene package and render runner, then checks:
  - the PNG digest matches the render evidence;
  - the evidence is bound to the scene package;
  - **pixel content**: under 20 % blown-out white, and over 2 % saturated label colour.

## Rendering defects found and fixed (pre-existing; affected earlier "real render" evidence)

Inspecting the first PL-0391 render showed a featureless white cube. The cause was three defects in the shared Blender pipeline:

1. **Factory default scene never cleared.** `--factory-startup` loads Blender's default 2 m cube, light and camera. The cube enclosed the 0.1 m package, and the camera framed it. **Every earlier real-render PNG (PL-0326 and later render smokes) therefore showed the default cube, not the package.** The earlier tests only checked metadata and pixel counts.
   - Fix: `_build_scene` now removes all pre-existing objects before importing the GLB and tags the imported body `packlab_scene_object`.
   - The render runner now raises `render_scene_foreign_mesh_present` if any untagged, non-presentation mesh is present.
2. **Axis frame mismatch.** The GLB keeps CAD Z-up source coordinates, but Blender's glTF importer assumes Y-up and bakes (x, y, z) → (x, −z, y). The label overlays, built in the source frame, were therefore misregistered: the boss stuck out sideways and a panel floated beside the body.
   - Fix: the imported body is rotated −90° about X back into the source frame.
3. **Overexposure.** The preset light power is fixed (1200/650/950 W), but lights are placed at multiples of the scene span. A small package was therefore lit about 10× too brightly and rendered pure white.
   - Fix: the runner scales each light's power by `(scene_span_m / 3 m)²` (inverse-square law). The preset values are unchanged and the scene span is measured in Blender metres.

Every Blender suite passes against the real executable: 59 tests (real smokes, render, batch, preset, GLB export, scene package, provenance, overlay, PL-0391).

## Limits

- The artwork is a synthetic 2×2 PNG, not POVU artwork.
- No print, colour, physical-fit or manufacturing validation is claimed.
- The real-render test runs only on a machine with the approved Blender; hosted CI runs the lineage test only.
- The render evidence `light_facts` records the preset watts; the effective scaled power is not yet recorded (P3).

## Review outcome

`CLAUDE_PEER_REVIEW_PL0390_0392_V01.md`: PASS. P2-1 found that artwork renders rotated 180° on the flat faces, because nothing in the pipeline defines which way is "up" for artwork. This is a known limitation at acceptance, and a follow-up is in progress.
